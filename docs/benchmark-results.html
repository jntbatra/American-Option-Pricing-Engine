American option pricing on GPU

Five backends — serial, OpenMP, CUDA, and quasi-Monte Carlo variants of the last two — pricing Bermudan options by Longstaff-Schwartz. After replacing the source paper's perfect-foresight upper-bound estimator the pricer agrees with the exact Black-Scholes value to 1.7 × 10−5, where that estimator was 56% high. Profiling then moved the GPU from 19× to 53× serial — and turned up an overflow bug on the way.

Correctness

The paper computes an upper bound, reported as a price

Cvetanoska & Stojanovski value each path with max(intrinsic, discounted continuation) using that path's own realised future — which, in the paper's own words, "assume[s] that all future values … are known" and "gives the upper bound value." Every path exercises with hindsight, so the estimate grows with the number of exercise dates and never converges. Not a hidden bug: the paper reports this divergent upper bound as a price and never applies the Longstaff-Schwartz method it cites.

Why a call alone cannot prove this works

For a call on a non-dividend-paying stock, never exercising early is the correct answer — so the test above cannot distinguish a working exercise rule from one that never fires. The put is the real test: early exercise binds, there is no closed form, and a Cox-Ross-Rubinstein tree restricted to the same 20 exercise dates gives an independent reference that shares no code with the Monte Carlo path.

Convergence

Quasi-random sampling buys about an order of magnitude

Both estimators price the same contract. The pseudo-random backends fall off at the textbook O(N−1/2) rate; the Sobol sequence with a Brownian bridge converges markedly faster.

The standard-error column does not apply to QMC

The sd/√N formula assumes independent draws, and a Sobol sequence is deterministic and correlated by construction. At N=10⁶ the QMC backends report a standard error of 0.0143 while their actual error against the exact price is 0.000014 — a thousandfold overstatement. The benchmark prints this warning at run time. A real QMC error bar needs randomised QMC: average over several independent digital shifts and take the standard deviation of the means. That is not yet implemented.

Optimisation

Profiling first, then three fixes

The first working version ran 19× serial, which is poor for an embarrassingly parallel problem. Rather than guess, the launcher was instrumented to split device time into path generation and the LSM backward pass. The measurement contradicted the obvious hypotheses twice.

StageCUDA LCGCUDA QMCShare

Two hypotheses the profiler killed

“The host round trips dominate.” The backward pass synchronises 19 times to solve each 3×3 regression on the CPU. That looked like the obvious culprit and it is not: it accounts for well under a millisecond of a 56 ms pass.

“The strided reads dominate.” Paths were stored point-major, so at a fixed timestep consecutive threads read 168 bytes apart — textbook uncoalesced access. Switching the device layout to time-major changed the runtime by under 2%. The layout is still correct and was kept, but it was not the bottleneck.

What actually dominated was plain FP64 arithmetic. Path generation is transcendental-heavy — one exp per step, plus two logs in Moro's tail branch — and this GPU runs double precision at 1/64 of its single-precision rate.

Storing paths in fp32

Path storage and generation drop to single precision; the regression keeps accumulating in double, because ATA's entries scale with N and summing four million terms in float would lose far more than the paths ever could. Both instantiations live in the same binary, so one run prices the same contract both ways and reports the difference rather than asserting it is small.

The price moves by 8×10⁻⁶ — roughly a thousandth of the Monte Carlo standard error at this path count, so the change is invisible against the statistical noise it sits inside. The QMC backend gains nothing, and shouldn't: its Sobol points and Brownian bridge stay double on purpose, since the low-discrepancy structure is the entire reason that backend exists.

The fp32 experiment surfaced a real bug

At four million paths the single-precision run returned inf. __uint2float_rn(0xFFFFFFFF) rounds up to exactly 2³², so the float LCG can emit exactly 1.0, and Moro then evaluates log(−log(0)). The same hole existed in the double path — LCG state 0 gives u = 0 — merely rare enough never to have fired. Both are now clamped inside Φ⁻¹ itself, where the function is genuinely undefined, rather than at the four call sites.

Cheaper reduction

The regression accumulator reduced its nine statistics with nine separate block reductions, each carrying a __syncthreads — 171 full block barriers across a 20-date sweep. Warp shuffles are warp-synchronous and need no barrier, so only the cross-warp stage has to be fenced. Folding it to one barrier, and dropping a redundant tenth counter (the constant basis function means ATA's leading entry already counts the in-the-money paths), took the backward pass down 13%.

Caveats

What these numbers do not show

  • The GPU is handicapped here. The RTX 5060 runs double precision at 1/64 the single-precision rate, and CUDA 12.4 has no native sm_120 target so the kernels arrive by PTX JIT from sm_80. Everything on the device is deliberately double precision, to make CPU/GPU agreement testable rather than to be fast — the two QMC backends match to 1 × 10−6. On a datacenter part with full-rate FP64 the speedup column should look very different.
  • LSM is low-biased. The fitted exercise policy is suboptimal, so the estimator converges from below. A true confidence interval needs a paired upper bound (the Andersen-Broadie dual), which is not implemented.
  • The pseudo-random streams are not independent. Path seeds are (path_id + 1) × 1234567 on a 2³² LCG, so neighbouring paths walk correlated positions on the same lattice. Replacing this with a counter-based generator (cuRAND Philox) is the next correctness item.
  • Memory now bounds the problem. LSM regresses across paths at each exercise date, so the whole path set must be resident — N×(m+1) doubles, about 176 MB at N=10⁶, m=21. The naive recursion needed none of it.
